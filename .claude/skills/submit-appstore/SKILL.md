# Отправка обновления GARAJ.KG в App Store

Весь процесс — три воркфлоу GitHub Actions, вручную в App Store Connect ничего
делать не нужно. Проверено вживую 11.07.2026: версия 1.0.1 (билд 413) отправлена
на ревью Apple именно этим путём.

## Полный цикл релиза (по порядку)

1. **Поднять версию** (только если начинаем НОВУЮ версию, не было ещё сборок):
   в `.github/workflows/build-ios.yml` найти `IOS_VERSION_NAME: "1.0.1"` и
   поднять (напр. `"1.0.2"`) — App Store не принимает билды на уже
   выпущенную версию. Закоммитить и замержить в main.

2. **Собрать билд**: Actions → воркфлоу **build-ios** → Run workflow (ветка
   main, инпутов нет). Номер билда = `run_number` этого воркфлоу (виден в
   списке ранов). Сборка сама заливается в TestFlight в конце (~5 минут).
   Все шаги должны быть success, включая «Залить в TestFlight».

3. **Дождаться обработки Apple** (5–30 мин после заливки): Actions →
   **submit-appstore** → Run workflow → `mode=status`, `version=X.Y.Z`,
   `build=<номер>`. В логе ждать `processingState=VALID`. Режим status
   ничего не меняет — безопасен всегда, гонять сколько угодно.

4. **Отправить на ревью**: тот же воркфлоу, `mode=submit`. Что он делает:
   создаёт версию в ASC (если нет; сразу с авто-релизом после одобрения) →
   прикрепляет билд → заполняет ТОЛЬКО ПУСТЫЕ What's New / демо-вход /
   контакты ревью (заполненное основателем НЕ перетирается; скриншоты и
   описание переезжают с прошлой версии сами) → создаёт заявку на ревью →
   отправляет. Успех = строка `=== ОТПРАВЛЕНО НА РЕВЬЮ APPLE ===` в логе.

5. **Проверить**: `mode=status` ещё раз — версия должна быть
   `WAITING_FOR_REVIEW`. Дальше ждать вердикт Apple (обычно 1–2 дня, письмо
   на почту). Одобрение → версия публикуется САМА (авто-релиз).

## Режимы воркфлоу submit-appstore

| mode | Что делает | Опасность |
|---|---|---|
| `status` | Только читает: версии и их состояния, билд и его обработка, What's New, ревью-заметки, заявки | Нулевая — это диагностика |
| `submit` | Создать версию → прикрепить билд → добить пустые метаданные → отправить на ревью | Отправляет Apple; отменить можно в ASC пока ревью не началось |
| `autorelease` | Переключить существующую версию на авто-релиз после одобрения | Минимальная |

## Механика (если нужно чинить)

- Работает через **App Store Connect API** (не altool): JWT ES256 из секретов
  `APPSTORE_API_KEY_ID` / `APPSTORE_API_ISSUER_ID` /
  `APPSTORE_API_PRIVATE_KEY_BASE64` — те же, которыми build-ios заливает в
  TestFlight. Ключ должен иметь роль App Manager (иначе POST/PATCH → 403).
- Флоу отправки — современный `reviewSubmissions` (старый
  `appStoreVersionSubmissions` деприкейтнут): POST reviewSubmissions → POST
  reviewSubmissionItems (версия) → дождаться `appVersionState ==
  READY_FOR_REVIEW` → PATCH `submitted: true`. Контракт сверен с
  fastlane/deliver и доками Apple 11.07.2026.
- Вопрос экспорт-шифрования Apple не задаёт: `ITSAppUsesNonExemptEncryption
  = false` зашит в Info.plist сборки (mobile/scripts/inject-ios-permissions.mjs).
- Демо-вход для ревьюера обязателен: номер `996700000001` (env
  `DEMOOTPPHONES` в Vercel, код показывается на экране) — воркфлоу впишет
  его сам, если поле пустое. Env в Vercel НЕ снимать.

## Частые ошибки

- «Билд ещё НЕ виден в ASC» / `processingState=PROCESSING` — рано, Apple ещё
  обрабатывает. Подождать 10–20 минут, повторить.
- 409 при POST reviewSubmissions — уже есть активная заявка (одна на
  платформу). Смотреть `mode=status`: заявка `READY_FOR_REVIEW`
  переиспользуется автоматически; зависшую отменять в ASC (или PATCH
  `canceled: true`).
- 409 при создании версии — версия уже существует (например, отклонённая
  ревью): воркфлоу сам найдёт и переиспользует её по `versionString`.
- Ошибка ENTITY_ERROR при submit — Apple перечисляет, чего не хватает
  (обычно пустой What's New у какой-то локали или скриншоты) — читать
  `errors[].detail` в логе.

## Если Apple отклонила

Ответы на типовые отказы — `APP-STORE-REJECTION-PLAYBOOK.md` в корне репо.
После фикса: новый билд (шаг 2) → `mode=submit` с новым номером билда.
